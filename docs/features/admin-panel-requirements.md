# 音声管理画面 要件定義書

作成日: 2025-01-11  
作成者: 開発チーム  
ステータス: 要件確定（実装前）

## 1. 概要

### 1.1 目的
Miraimアプリケーションで使用する音声ファイルと会話シナリオを効率的に管理するための管理画面を構築する。

### 1.2 背景
現在、音声ファイルのURLをコード内にベタ書きしており、コンテンツの追加・更新が困難な状況。開発チームが日常的に使用できる管理インターフェースが必要。

### 1.3 スコープ
- 音声ファイルのアップロード・管理
- 会話シナリオのテキスト編集
- シャドーイング用テキストの管理
- 音声とシナリオの紐付け

## 2. ユーザー要件

### 2.1 対象ユーザー
- **利用者**: 開発チーム（3-4名）
- **利用頻度**: 毎日（日常的な運用）
- **技術レベル**: エンジニア（技術的な操作は問題なし）

### 2.2 ユースケース
1. 新しい会話シナリオの追加と音声ファイルのアップロード
2. 既存シナリオのテキスト編集
3. シャドーイング練習用の音声とテキストのセット登録
4. 音声ファイルの差し替え・更新
5. シナリオと音声の紐付け管理

## 3. 機能要件

### 3.1 必須機能（Priority 1）

#### 3.1.1 音声ファイル管理
- **ドラッグ&ドロップアップロード**
  - 複数ファイル同時アップロード対応
  - アップロード進捗表示
  - エラーハンドリング

- **URL自動生成＆コピー機能**
  - Azure Blob StorageへのアップロードとURL生成
  - ワンクリックでクリップボードにコピー
  - URL履歴の保持

- **シナリオと音声の紐付け管理**
  - アップロード時に紐付け先シナリオを選択
  - ID/タグベースの自動紐付け機能
  - ファイル名の自動生成と手動編集
  - 紐付け状態の可視化

- **音声ファイル解析機能**
  - 音声の長さ（秒数）を自動取得・表示
  - 最初の5秒間の自動文字起こし（Whisper API使用）
  - 音声プレビュー再生
  - 音声品質チェック（音量、サンプルレート、無音検出）

#### 3.1.2 データ編集機能
- **会話シナリオ編集**
  - シナリオテキストの追加・編集・削除
  - レベル設定（beginner/advanced）
  - カテゴリ分類

- **シャドーイングテキスト管理**
  - 音声に対応するテキストの登録
  - タイムスタンプ設定（オプション）
  - 難易度設定

### 3.2 追加機能（Priority 2）

#### 3.2.1 音声ファイル処理
- **フォーマット変換**
  - MP3/WAV/M4A相互変換
  - ビットレート調整
  - ファイルサイズ最適化

- **プレビュー機能**
  - アップロード前の音声確認
  - 波形表示
  - 再生速度調整

#### 3.2.2 データ管理
- **一括操作**
  - CSVインポート/エクスポート
  - 一括更新
  - バックアップ機能

### 3.3 将来的な拡張機能（Priority 3）
- 音声自動生成（TTS）
- 音声文字起こし（STT）
- バージョン管理
- 変更履歴トラッキング
- 承認ワークフロー

## 4. 技術要件

### 4.1 アーキテクチャ
- **フレームワーク**: Streamlit
- **デプロイ先**: Streamlit Cloud
- **ストレージ**: Azure Blob Storage
- **データベース**: 既存のMySQL（Azure Database for MySQL）

### 4.2 技術仕様

#### 4.2.1 音声ファイル
- **対応フォーマット**: MP3, WAV, M4A
- **ファイルサイズ制限**: 50MB以下（要調整）
- **命名規則**: 
  - 自動生成: `scenario_{id:03d}_{type}_{date}_{hash[:6]}.{ext}`
  - 例: `scenario_001_greeting_20250111_abc123.mp3`
  - ユーザーによる編集可能
- **保存先**: Azure Blob Storage Container
- **音声解析**:
  - Whisper API（OpenAI）による文字起こし
  - pydubによる音声情報取得（長さ、音量、形式）

#### 4.2.2 データベース連携
- **接続方式**: SQLAlchemy経由
- **対象テーブル**:
  - `conversation_scenarios`: 会話シナリオ
  - `shadowing_contents`: シャドーイング用コンテンツ
  - `audio_files`: 音声ファイルメタデータ（新規作成予定）

### 4.3 セキュリティ要件
- **認証方式**: シンプルなパスワード認証（全員共通）
- **通信**: HTTPS必須
- **アクセス制御**: Streamlit Cloudの環境変数でパスワード管理
- **監査**: アクセスログの記録

## 5. 非機能要件

### 5.1 パフォーマンス
- ファイルアップロード: 10MB/秒以上
- ページロード: 3秒以内
- データベース操作: 1秒以内

### 5.2 可用性
- Streamlit Cloudの無料プランSLA準拠
- 営業時間内（9:00-20:00）の利用を想定

### 5.3 ユーザビリティ
- 直感的なUI（ドラッグ&ドロップ）
- レスポンシブデザイン
- エラーメッセージの明確化
- 操作ガイドの表示

### 6.2 主要画面

- ドラッグ&ドロップエリア
- ファイル情報表示（ファイル名、サイズ、形式、長さ）
- 音声プレビュー再生エリア

- ファイル名自動生成・編集フィールド
- タグ選択（複数選択可）

- データテーブル（編集可能）
- フィルター・検索機能
- 音声紐付けドロップダウン
- 保存・キャンセルボタン

## 7. データモデル

### 7.1 音声ファイルメタデータ
```python
class AudioFile:
    id: int                    # 主キー
    original_name: str         # 元のファイル名
    storage_name: str          # 保存時のファイル名（自動生成/編集可）
    url: str                   # Blob Storage URL
    format: str                # MP3/WAV/M4A
    size: int                  # ファイルサイズ（バイト）
    duration: float            # 再生時間（秒）
    transcript_preview: str    # 最初の5秒の文字起こし
    scenario_id: int           # 紐付けシナリオID（nullable）
    uploaded_at: datetime      # アップロード日時
    uploaded_by: str           # アップロードユーザー
    tags: str                  # タグ（カンマ区切り）
    quality_check: dict        # 品質チェック結果（JSON）
```

### 7.2 既存テーブルとの関連
- `conversation_scenarios.audio_url` → `audio_files.url`
- `shadowing_contents.audio_id` → `audio_files.id`

## 9. 環境設定

### 9.1 環境変数
```bash
# Streamlit Cloud Secrets

AZURE_STORAGE_CONNECTION_STRING=xxxxx   # Azure Blob Storage接続文字列
```

### 9.2 必要なAzureリソース
- Azure Blob Storage Account
- Container: `audio-files`（パブリックアクセス可）

## 10. リスクと対策

### 10.1 技術的リスク
| リスク | 影響度 | 対策 |
|--------|--------|------|
| Streamlit Cloudの制限 | 中 | 必要に応じてAzure移行 |
| ファイルサイズ制限 | 低 | チャンク分割アップロード |
| 同時編集の競合 | 中 | 楽観的ロック実装 |

### 10.2 運用リスク
| リスク | 影響度 | 対策 |
|--------|--------|------|
| 誤操作によるデータ削除 | 高 | 論理削除＋定期バックアップ |
| 不正アクセス | 中 | IP制限検討 |
| ストレージコスト増大 | 低 | 定期的な不要ファイル削除 |
